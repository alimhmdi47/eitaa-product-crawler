# 🚀 Eitaa Intelligent Crawler & Analyzer
این پروژه یک پایپ‌لاین هوشمند برای جستجو، استخراج و تحلیل داده‌های پیام‌رسان ایتا (Eitaa) است. سیستم با استفاده از پروتکل اختصاصی ایتا جستجو را انجام داده، کانال‌های مرتبط را پیدا می‌کند و با استفاده از هوش مصنوعی (Groq/Llama3) تشخیص می‌دهد که آیا کانال مورد نظر فروشگاه است یا خیر. در نهایت داده‌های تایید شده در دیتابیس MongoDB ذخیره می‌شوند.

# 🛠 معماری سیستم
این سیستم از پنج بخش اصلی تشکیل شده است که به صورت موازی (Asynchronous logic) با هم در ارتباط هستند:

Main Finder Engine: وظیفه جستجوی کلمات کلیدی استراتژیک و یافتن یوزرنیم‌های جدید را دارد.

AI Shop Detector: در مرحله اول، محتوای کانال را بررسی کرده و در صورت تایید "فروشگاه بودن"، آن را به صف پردازش می‌فرستد.

AI Product Processor: به عنوان مغز متفکر میانی، پست‌ها را تحلیل کرده و جزئیات محصول (نام، قیمت، سایز و...) را استخراج می‌کند. این بخش دارای مدیریت هوشمند Rate Limit برای Groq است.

Redis Buffer: مدیریت دو صف مجزا (CHANNELS_QUEUE و PRODUCTS_QUEUE) برای تضمین عدم گم شدن داده‌ها.

Database Worker: ورکر نهایی که داده‌های پارس شده را در MongoDB ذخیره می‌کند.

# 🔍 نحوه کارکرد بخش‌ها
Scraper: ارسال درخواست‌های باینری به ایتا، استخراج یوزرنیم‌های خام و جمع‌آوری Bio/Posts.

Detector (Analyzer): فیلتر اول AI برای تشخیص ماهیت کانال؛ اگر فروشگاه باشد، آن را به صف CHANNELS_QUEUE می‌فرستد.

Processor: مغز متفکر سیستم؛ پست‌ها را از صف برداشته، جزئیات محصول (قیمت، نام و...) را استخراج و به صف PRODUCTS_QUEUE منتقل می‌کند.

Worker: مصرف‌کننده نهایی؛ محصولات آماده را از صف برداشته و در MongoDB ذخیره می‌کند (با قابلیت بازیابی در صورت خطا).

Session Service: مدیریت چرخش اکانت‌ها و پروکسی‌ها برای دور زدن محدودیت‌های نرخ درخواست (Rate Limit).

# 🛡️ نحوه مدیریت محدودیت‌ها و دور زدن Rate Limit ایتا
ایتا دارای مکانیزم‌های کنترلی شدیدی روی تعداد درخواست‌ها است. برای پایداری سیستم، راهکارهای زیر پیاده‌سازی شده است:

مدیریت هوشمند نشست‌ها (Multi-Session Management): سیستم با استفاده از کلاس SessionManager قابلیت تعریف و چرخش (Rotation) بین چندین اکانت مختلف را دارد. هر درخواست به صورت توزیع‌شده بین اکانت‌ها تقسیم می‌شود تا بار روی یک شماره موبایل متمرکز نشود.

استراتژی بازگشت (Back-off Strategy): در صورت دریافت خطای محدودیت (مانند کد ۴۲۹ یا وضعیت LIMITED)، سیستم به جای تلاش مجددِ بلافاصله، از یک مکانیزم وقفه هوشمند استفاده می‌کند تا اکانت‌ها مسدود نشوند.

شبیه‌سازی هدرهای باینری: برای جلوگیری از شناسایی توسط سیستم‌های آنتی‌بات، هدرهای پکت‌های باینری به گونه‌ای طراحی شده‌اند که دقیقاً رفتار نسخه وب ایتا را شبیه‌سازی کنند (استفاده از شناسه‌های اختصاصی نسخه وب).

چرخش پروکسی: سیستم از قابلیت استفاده از پروکسی‌های مختلف برای هر سشن پشتیبانی می‌کند تا آدرس‌های IP نیز به صورت دوره‌ای تغییر کنند.

# 🤖 توضیح پرامپت‌های استفاده شده برای هوش مصنوعی (AI Prompts)
۱. پرامپت تشخیص فروشگاه (analyze_with_ai)
این پرامپت وظیفه اعتبارسنجی کانال (Channel Validation) را بر عهده دارد تا کانال‌های نامرتبط از چرخه حذف شوند.

نقش (Persona): هوش مصنوعی به عنوان یک "Professional Data Validator" عمل می‌کند.

داده‌های ورودی: نام کاربری، نام کانال، Bio و ۵ پست آخر کانال برای بررسی جامع ارسال می‌شوند.

معیارهای تصمیم‌گیری: به مدل دستور داده شده تا به دنبال نشانه‌های فروشگاهی مانند قیمت (تومان)، آیدی ادمین سفارش و اطلاعات ارسال باشد.

خروجی مطلوب: برای سرعت در پردازش و سادگی در فیلتر کردن، خروجی به فرمت "YES/NO" به همراه یک دلیل کوتاه فارسی محدود شده است.

Temperature: مقدار 0.1 تنظیم شده تا پاسخ‌ها کاملاً منطقی و بدون خلاقیت اضافی (Deterministic) باشند.

۲. پرامپت تولید کلمات کلیدی (generate_advanced_keywords)
این پرامپت مرحله کشف هوشمند (Discovery Phase) را مدیریت می‌کند.

استراتژی Root + Attribute: مدل موظف است برای هر محصول، هم نام پایه (مانند مانتو) و هم ترکیب سئوشده (مانند مانتو کتی) را تولید کند تا بیشترین پوشش در جستجوی ایتا ایجاد شود.

محدودیت‌های فنی: با توجه به محدودیت‌های جستجوی ایتا، استفاده از حرف "و" به طور کامل ممنوع شده و خروجی فقط به صورت کلمات جدا شده با ویرگول درخواست شده است.

خوشه‌بندی (Clustering): حوزه‌های پوشاک، آرایشی، خانگی، دیجیتال و بدلیجات به عنوان خوشه‌های هدف به مدل داده شده‌اند تا تنوع محصولات حفظ شود.

۳. پرامپت استخراج جزئیات محصول (extract_bulk_products)
این پرامپت مربوط به بخش امتیازی (Bonus Feature) مستند است که وظیفه تبدیل متن غیرساختاریافته به داده‌های ارزشمند را دارد.

تحلیل دسته‌ای (Bulk Analysis): برای کاهش مصرف توکن و تعداد درخواست‌ها به Groq، چندین پست به صورت یکجا برای تحلیل ارسال می‌شوند.

استخراج موجودیت‌ها: مدل وظیفه دارد فیلدهای نام محصول، سایز، رنگ، جنس و قیمت را با دقت استخراج کند.

فرمت خروجی (Strict JSON): خروجی دقیقاً در قالب یک شیء JSON استاندارد تعریف شده است تا بدون نیاز به پردازش اضافی، مستقیماً در صف Redis و سپس MongoDB ذخیره شود.

Temperature: مقدار 0 تنظیم شده تا استخراج داده‌ها با بالاترین دقت و کمترین خطا انجام شود.
